Kedua kurva menunjukkan laju pertumbuhan linier proporsional terhadap ukuran masukan N karena panjang pola (m) konstan. Namun, algoritma rekursif menanggung overhead call stack frame, alokasi memori heap untuk pemotongan indeks array, dan context switching JavaScript V8 engine pada kedalaman rekursi tinggi.

Perbandingan Implementasi Algoritma

Naive Matching — Iteratif
Time: O(n·m) · Space: O(1) 
01  function naiveIterative(text, pattern):
02    n = length(text)
03    m = length(pattern)
04    matches = []
05    for i = 0 to n - m:
06      j = 0
07      while j < m and text[i + j] == pattern[j]:
08        j = j + 1
09      if j == m:
10        matches.append(i)
11    return matches

Eksekusi linier berurutan murni dengan dua pointer indeks flat register. Tidak memicu alokasi frame stack baru di luar variabel primitif ringkas.

Naive Matching — Rekursif
Time: O(n·m) · Stack: O(log N + n) 
01  function naiveRecursive(text, pattern, i = 0):
02    n = length(text), m = length(pattern)
03    if i > n - m:
04      return []
05    isMatch = checkChar(text, pattern, i, 0)
06    subResult = naiveRecursive(text, pattern, i + 1)
07    if isMatch:
08      return [i] + subResult
09    return subResult

Menerapkan Divide & Conquer recursive stepping. Memerlukan penumpukan stack frames sejumlah N, yang menjelaskan delta waktu ekstra pada pengujian N berskala besar.
